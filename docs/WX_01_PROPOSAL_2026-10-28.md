## The student experience

One optional **Airport weather** section in a lesson's Preparation area; Daily Plan's next-flight area opens that section.
Keep one shared view, not another weather dashboard. A school, instructor and home airport remain optional.
Settings offers **Show airport weather**, recommended default **OFF**, with: “Gets reports from NOAA/NWS for the airport you enter.”
Turning it on reveals one field, **Airport ICAO code**, and two buttons: **Get observation** and **Get forecast**.
Each button sends one request for its report; opening preparation, typing and enabling the setting send nothing.
She can read both reports after requesting each. No “get both” action silently doubles the request count.

Show the selected code and returned station name, source “NOAA/NWS Aviation Weather Center”, then:

- **Observation (METAR)**: a short plain-words summary, full original report, observed time and observation age.
- **Forecast (TAF)**: a plain-words summary with each period's times, full original report, issued time/age and validity start/end.
- For each report: last successful fetch time and fetch age, distinct from report age; full dates and UTC labels, with optional labelled local time.

Always show **“For lesson preparation. Check official sources and your instructor.”**, including empty and error states.
Never say safe/unsafe, fly/don't fly, suitable, ready or cleared; no recommendation, flight-category badge, traffic light or alert notification.
Fetching never completes “Weather review”, changes preparation counts, rates proficiency or reschedules a lesson.
Weather remains current report context; it is not a forecast for the lesson unless its displayed validity actually covers that time.
Use readable wrapping raw text, labelled controls, keyboard access, polite status announcements and stable focus.

| State | Calm text and behavior |
| --- | --- |
| Nothing requested | “Enter the airport's four-letter ICAO code to look at its reports.” |
| No observation / no TAF | “No observation returned for this airport” / “No forecast returned for this airport.” Keep the other report usable. |
| Unavailable / timeout / unreadable | “Weather couldn't be updated. Try again later.” Retain any earlier report with its original times and a previous-report label. |
| Offline | “Weather couldn't be reached. You may be offline.” Show a previous report only if still in memory; never infer connectivity from browser status alone. |
| Stale / expired / not yet valid | Say “Older observation”, “Last checked … ago”, “Forecast has ended” or “Forecast starts …”; keep the exact times visible. |
| Rate limited | “The weather service needs a pause. Try again after …”. Disable requests until the native cooldown ends. |

## Verified official contract and proposed requests

Checked read-only on 28 October 2026: [AWC Data API and usage rules](https://aviationweather.gov/data/api/#using-the-api),
[official OpenAPI v4.0 YAML](https://aviationweather.gov/data/schema/openapi.yaml), and [METAR/TAF product explanations](https://aviationweather.gov/help/data/).
The web reader could not decode the YAML's content type; direct HTTPS retrieval succeeded. No weather endpoint was called.
The documentation URL `/data/api/` is not the request base; the actual paths are `/api/data/...`.

| Product | Exact proposed GET; `{ICAO}` is the validated field value |
| --- | --- |
| METAR | `https://aviationweather.gov/api/data/metar?ids={ICAO}&format=json&hours=2` |
| TAF | `https://aviationweather.gov/api/data/taf?ids={ICAO}&format=json&time=valid` |

`ids` selects stations; `format=json` selects decoded JSON arrays, including original text.
`hours=2` is our bounded observation lookback; `time=valid` selects TAF processing by validity rather than issuance.
Omit `date` to avoid requesting historical products; no lesson time, bounding box or coordinates are sent.
Both products also document raw, GeoJSON, XML and IWXXM formats; use JSON only in this slice.
METAR's `taf` and TAF's `metar` inclusion parameters exist, but do not use an unproven combined JSON shape.

| JSON fields used | Native interpretation |
| --- | --- |
| METAR `icaoId`, `rawOb`, `obsTime` | Exact station, untouched raw text, observation Unix seconds. |
| TAF `icaoId`, `rawTAF`, `issueTime`, `validTimeFrom`, `validTimeTo` | Exact station, raw text, issue timestamp string, validity Unix seconds. |
| Decoded conditions / TAF `fcsts` | Local summary input only; preserve units and period/change qualifiers. |

Normalize trim/case and require exactly four ASCII letters; reject commas, state selectors, URLs and controls in Rust too.
Do not infer ICAO by prefixing an IATA/local code, parsing the free-text lesson location, using GPS or sending profile.homeAirport automatically.
Accept only matching `icaoId` records; check the station in raw text too. Display the returned name for her to check.
Four letters validate syntax, not airport existence. A mismatch must never be displayed as that airport's weather.
Only the airport's own station in 01b: no nearest METAR/TAF substitution, radius search or airport directory download.
No TAF returned does not prove the airport never issues one; it means none was returned now. Do not borrow another airport's forecast.
Handle documented HTTP 204 and an empty JSON array as no data, independently for each product.
Within a bounded array choose the newest matching METAR observation; for TAF use the newest applicable issuance, respecting amendments/cancellation.
Before implementation, recheck schema revision, current-query selection/order, issue-time syntax, amendment/NIL/CNL representation and forecast units.
Those details need decoder fixtures and explicit refusal/fallback behavior; this plan claims no live response compatibility.

## Plain words, time and authority

Summaries are deterministic local formatting of decoded fields, **not Gemini** and not a complete briefing.
For example, fictional values can read “Wind from 220° at 7 knots, gusting to 12. Visibility greater than 6 statute miles.”
Identify observation versus forecast. Keep FM, TEMPO, BECMG and probability groups distinct with their own intervals; never flatten them into certainty.
Missing values mean “not reported”, not zero/calm/clear. Unknown codes or undecoded segments say “Some details are only in the original report.”
If interpretation is uncertain, omit that summary part; preserve readable raw text. NIL/CNL must not yield a normal conditions summary.
Use explicit units: decoded wind knots, visibility statute miles, cloud bases feet; METAR decoded altimeter is hPa, not inHg.
Do not invent a METAR validity end, treat receipt time as observation time, or infer a whole date from DDHHMMZ without a trusted date anchor.

Recommended trial labels: METAR older than 90 minutes → older observation; fetch older than 15 minutes → last check is old.
TAF issue age over 6 hours → older forecast; outside `[validTimeFrom, validTimeTo)` → not yet valid/ended regardless of fetch age.
These are conservative display policies for review, not official expiry rules or operational thresholds; a just-fetched report can already be old.
Reject impossible/reversed intervals; missing/unparseable or over-5-minute-future observation/issue times get “Report time couldn't be checked”.
Recompute age on view/open and a local display timer without network. Wall-clock jumps invalidate age confidence; never clamp negative age to “just now”.
Use monotonic time for request budgets/cooldowns, UTC instants for report comparisons, and test local-zone/DST display separately.

## Native network boundary

Existing route: `src/services/gemini.ts` invokes registered commands in `src-tauri/src/lib.rs`; Rust owns HTTPS.
`src-tauri/src/gemini.rs:200` disables redirects; `:1879` bounds chunked response accumulation. Reuse those patterns, not Google's credentials or retry pipeline.
`src-tauri/Cargo.toml` already has reqwest/rustls and serde_json; no new dependency is proposed.
Propose a narrow station/product command, not an arbitrary URL proxy; native code builds a fixed HTTPS AWC URL and validates all inputs.
No webview fetch, remote script/image, HTTP plugin or CORS workaround. Keep `tauri.conf.json` CSP and `capabilities/default.json` unchanged.
Register only the narrow application command. Browser mode shows “Weather is available in the desktop app”; synthetic fixtures may exercise UI locally.
For 01b show/copy the official source URL as text. Native “Open official source” would need a later explicit AWC-only opener allowlist change;
today's opener allowlist covers AI Studio only. Do not claim an AWC external-link button already works or broaden permissions silently.

- One HTTP GET per button press, no automatic retry, no fetch on open, no background polling, focus/reconnect refresh or hidden prefetch.
- One in-flight request globally; disable duplicates. Switching airport, closing the view, turning OFF or restoring data cancels and invalidates late responses.
- Proposed limits: 5-second connection timeout, 15-second total deadline including body read; no redirects; normal TLS verification.
- Bound decoded body bytes to 256 KiB, including errors: reject excessive Content-Length early and enforce the cap while reading chunks without trusting that header.
  Reject unexpected encodings/content types, HTML, invalid UTF-8/JSON, over 64 records, over 64 forecast groups or raw text over 16 KiB; never render remote HTML.
- `User-Agent: HerFlightDeck/<app-version> (lesson-preparation-weather)` and `Accept: application/json`; no cookies, authorization, referrer or per-install identifier.
- AWC documents 100 requests/minute. Enforce at least 2 seconds between any requests plus 60 seconds per station/product, in native state.
- On 429 honor a valid Retry-After (seconds or HTTP date); otherwise 60-second pause, doubling repeated 429 pauses to at most 15 minutes.
  A longer server Retry-After wins. On 5xx/timeout use a 30-second manual-retry pause. Never schedule a retry when the pause ends.
- Only station ID is user-derived request data; format/lookback/time selectors and User-Agent are fixed protocol metadata. AWC still sees normal source IP/TLS metadata.
  No training history, lesson title/date/time, notes, documents, profile, key or coordinates leave the app; no proxy, analytics or Gemini call.
  Sanitize diagnostics to stage/status, not full URLs, raw reports, station history or arbitrary upstream error text.

## Storage and backups

Recommend **memory only**: one selected station with at most one validated METAR and one TAF plus fetch timestamps/status.
Keep earlier validated reports on failed refresh; never overwrite them with a partial body or claim an error refreshed their age.
A confirmed no-data response or cancelled forecast makes that product's previous report historical/unavailable, not current. Cache keys include product and ICAO.
Changing station clears its displayed/cache reports; OFF, restart and restore clear everything. Offline restart honestly has no saved weather.
No weather in SQLite, localStorage, managed documents, generation journals, lesson snapshots, brief/calendar/packet exports or any backup/safety copy.
Persist only the device's toggle using the existing local preference pattern in `src/lib/appearance.ts`; invalid/missing preference means OFF.
The airport field is session-only in 01b; do not repurpose a lesson's location or the profile settings row as a cache.
This avoids migration and automatic SQLite backup inclusion. Weather is replaceable reference data, not her training record.
If durable cache is later needed, return to the owner with a bounded separate cache design and backup exclusion proof.
A table would require an approved **add-only migration** and explicit export/safety-copy handling; merely adding a SQLite table does not exclude it from backups.

## Risks and synthetic acceptance

Main risks: wrong station, a stale report appearing current, a qualified forecast becoming a certainty, unbounded reads and privacy leakage.
Author fixtures shaped like the official schema with fictional stations `ZZZA`/`ZZZB`, invented reports/conditions and fixed dates; never query those IDs.
Cover mixed-case input, IATA/local-code rejection, station/raw mismatch, reordered/duplicate reports, SPECI/COR/AMD, NIL/CNL and no-TAF 204/empty arrays.
Cover calm versus missing wind, VRB/gusts, fractional/greater-than visibility, null cloud bases, VV/CAVOK, negative temperatures and unknown remarks.
Cover FM/TEMPO/BECMG/PROB overlap and omitted fields; prohibit unsupported summary claims and hPa/inHg confusion.
Test UTC midnight/month/year/leap rollovers, DST/local zones, exact age/validity boundaries, future times, clock rollback and resume after sleep.
Loopback-only fixtures exercise slow connect/headers/body, dropped connection, malformed/truncated JSON, HTML, oversized declared/chunked bodies,
redirects, unsupported encoding, 400/403/404/429 (Retry-After variants)/5xx, cooldowns, concurrent clicks, cancellation and out-of-order replies.
Assert one outbound request per action, none while OFF/on open/reconnect, no post-cancel publication, and no station/data leakage in errors/logs.
Assert no report bytes in database, localStorage, backup/safety copies or exports; test OFF/restart/restore invalidation and retained-report ages after failure.
Walk keyboard/VoiceOver, narrow layout/200% text, raw wrapping and independent product failures without changing checklist counts.
All tests use synthetic fixtures, injected clocks and loopback servers: no real profile, key, PDF, training data or live provider calls.
This planning round runs no app suite and establishes no native, installed, live-provider or release acceptance.
