## Versioned card reviews and continuity (approved C-D3)

Under explicit approved default C-D3 ('changed content starts fresh, identical A→B→A history retained; cross-version carryover deferred'), appending a card creates a new content-addressed version that starts with fresh cards. A prior manager classification mistakenly labelled this expected behavior as a bug. The observed canonical-repository test (rating 2 cards Easy then appending 1 card yields a current queue of 3 new cards with 0 rated states in the current snapshot, while prior raw rating states/events/operations remain deep-unchanged) is EXPECTED behavior, confirming that historical raw review audits are preserved and not silently erased or forged into fake events. Compact UI provides clear student disclosure ('Adding a card starts fresh reviews for this set. Earlier reviews stay saved with the previous version.'). No production data or schema changes were made.
