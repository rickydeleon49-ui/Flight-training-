## 1. Proposed User Outcome & Scope Boundaries

### Before and After Scenario
- **Current Main (Before):** Practice tests generated by Gemini or imported from packets live in `practice_tests` as an unversioned row with a raw JSON questions array. The existing test UI ([PracticeTestPanel.tsx](src/pages/StudyLibrary/PracticeTestPanel.tsx)) stores progress purely in React component state. If a student answers 8 questions on airspace weather minimums, switches to the Flight Deck to check an event, closes the window, or puts their Mac to sleep, all 8 responses and their progress vanish. Retaking resets the in-memory counter; past attempts leave no record. Regenerating a test immediately overwrites the single row, destroying any active session. Forcing a choice between options forces guessing when the student honestly does not know the answer.
- **Proposed Increment (After):**
  - **Resume Anywhere:** Starting a practice test creates an atomic `in_progress` attempt bound to a stable content version. Navigating away, closing the window, or restarting the application preserves every confirmed response. Reopening the material displays an honest resume banner (*"In progress — 8 of 15 answered"*).
  - **Explicit "I Don't Know":** An explicit choice alongside multiple-choice options. It is tallied separately from incorrect guesses and unreached questions, encouraging honest assessment.
  - **Trustworthy Completion:** Submitting the final question executes an atomic completion transaction that computes an immutable result snapshot (`correct`, `incorrect`, `dont_know`, `unanswered`, `score_percent`).
  - **Educational Review:** The completed screen displays the score alongside a breakdown of missed and skipped questions with explanations and source references.
  - **Version Isolation:** Regenerating a test or importing a new material creates a new active version. Completed past attempts remain immutably anchored to the exact questions and options the student answered.
  - **Clean Retakes:** "Retake this test" leaves the completed attempt intact in history and opens a fresh attempt on the latest active version.

### Explicit Scope Boundaries
- **Included in this increment:** Single-material practice tests (both Gemini-generated and imported); resumable in-progress attempts across restarts; atomic per-question persistence; explicit "I don't know" distinction; immutable completed attempt snapshots; review of missed and "I don't know" items; retake action; content versioning upon test regeneration; additive database migration (Migration 11) with restart-safe legacy upgrade.
- **Explicitly deferred to later roadmap increments:** Multi-material / library-wide quiz sessions; flashcard review scheduling (FSRS / review queue, M2-3); source navigation page jumps (M4); AI feedback question extraction; official FAA exam certification claims; oral exam simulation; replacement import flows (overwriting existing materials).

## 2. Implementation Architecture: Two Sequential Source PRs

We recommend dividing this milestone increment into **two sequential, reviewable PRs**:

```text
PR 1: Foundation, Migration & Persistence Contracts (Backend & Data Layer)
  ├── Migration 0011_practice_sessions.sql (additive DDL + triggers)
  ├── lib.rs CURRENT_SCHEMA_VERSION = 11 & backup validation updates
  ├── migrations.ts & migration-checksums.json registration
  ├── Restart-safe legacy migration runner (practice_tests -> versions/items)
  ├── Native atomic commands (rusqlite: start, respond, complete, retake)
  ├── Browser/test atomic mirror (sqlJsDb durable write + node:sqlite)
  ├── PracticeSessionRepository with exact contract types
  └── Shared contract & persistence regression tests (no UI changes)
        │
        ▼ (Merged to main after independent Codex review)
PR 2: User Interface, Accessibility & Interaction (Frontend Polish)
  ├── PracticeTestPanel.tsx (resume state, "I don't know", keyboard nav)
  ├── MaterialDetail.tsx (resume banner, past results summary, retake)
  └── UI integration & accessibility regressions (interruption, retry, aria-live)
```

**Tradeoff Rationale:** A single monolithic PR (~1,800 lines across Rust, SQL, TypeScript adapters, repositories, and React UI) combines data safety risks with interface revisions. Dividing the work isolates schema migrations, legacy conversion safety, atomic invariants, and backup/restore round trips into PR 1. Once data persistence is independently verified and merged, PR 2 implements the interactive components against proven repository contracts.

## 3. Owner Decision Table (Addressing M2S-R1)

The following decisions govern data retention, versioning, and product claims. Recommended defaults are presented with concrete alternatives:

| # | Decision | Recommended Default | Concrete Alternative | Rationale & Tradeoff |
|---|---|---|---|---|
| **D1** | **Source Deletion & Attempt Retention** | **Policy A (Retain Study Review for Completed Attempts):** Deleting a material deletes its PDF, active guide, and active test. Completed past attempts retain their frozen question text, options, explanations, student answers, and a `source_material_title` snapshot (`source_material_id = NULL`, `is_active = 0`). Inactive versions with zero completed attempts and all unfinished/draft attempts are pruned. An explicit "Erase study history" action allows purging all records. | **Policy B (Strict Summary Only):** Delete all questions, options, and responses on material deletion. Keep only aggregate numbers (`source_material_title`, `started_at`, `completed_at`, `score_percent`, `correct_count`, `total_questions`).<br><br>**Policy C (Full Cascade Wipe):** Delete all attempts, versions, items, and responses on material deletion. | Policy A ensures student study history and review value are not lost when an obsolete PDF is pruned from the library. Storing retained text takes ~5–20 KB per completed test version. Policy B saves space but permanently destroys the ability to review missed questions. Policy C treats tests as disposable. |
| **D2** | **Regeneration vs. In-Progress Session** | **Abandon with notice:** Regenerating a practice test creates a new active version. Any *in-progress* attempt on the prior version is transitioned to `abandoned` with notice: *"Practice test was regenerated; unfinished attempt closed."* Completed attempts remain intact on their version. | **Disallow regeneration while test in progress:** Prevent the user from regenerating until the current attempt is either finished or explicitly cancelled. | Abandoning avoids scoring responses against replaced question keys while letting the user regenerate when desired. Completed history remains unaltered. |
| **D3** | **Session Scope** | **Single-material only:** Practice tests are strictly scoped to one selected study material in this increment. | **Multi-material quiz pools:** Allow cross-material custom test generation immediately. | Single-material delivers immediate daily utility without introducing complex cross-material schemas or query bottlenecks. |
| **D4** | **Legacy Corrupt `questions_json`** | **Safe skip with durable status:** If an existing `practice_tests` row contains malformed JSON or zero valid questions, record `legacy_error = 'MALFORMED_JSON'`, skip version creation, leave the row intact, and display an honest UI notice: *"Existing test could not be migrated; please regenerate."* | **Fail migration:** Abort database upgrade on malformed historical JSON. | The application must start safely even if an older Gemini call stored malformed JSON. The migration never aborts or drops unmigrated data silently. |
| **D5** | **Practice Score Wording** | **Informational practice label:** Display *"Practice result from your material ({n}%). Not an official FAA knowledge test score or certification of flight readiness."* | **Generic score display:** Show only "{n}% correct" without regulatory context. | Meets product truthfulness standards (ROADMAP §2) and prevents false confidence regarding FAA knowledge exam readiness. |

## 5. Backup, Restore & Downgrade Specification (Addressing M2S-R3)

- **Database Format Version:** Migration 11 increments `CURRENT_SCHEMA_VERSION` in [src-tauri/src/lib.rs](src-tauri/src/lib.rs) from 10 to 11.
- **Backup Creation:** Existing backup engine ([src-tauri/src/backup.rs](src-tauri/src/backup.rs)) captures the SQLite database file and document directory into a ZIP archive. The new tables are inside the primary database and are backed up automatically.
- **Semantic Restore Validation:** In addition to checking SQLite integrity and table presence, `backup.rs::verify_application_database` will execute targeted semantic checks:
  1. Verifies presence of `practice_test_versions`, `practice_test_items`, `practice_attempts`, and `practice_responses`.
  2. Verifies that every item references an existing version (`NOT EXISTS (SELECT 1 FROM practice_test_items i LEFT JOIN practice_test_versions v ON i.version_id = v.id WHERE v.id IS NULL)`).
  3. Verifies that every response references an item belonging to the attempt's version.
  4. Verifies migration ceiling: an archive with migration version > 11 is rejected with *"That backup was created by a newer database format. Update the app first."*
- **Older Archive Upgrade:** Restoring a backup created by an older version (schema 1–10) unpacks cleanly; application startup runs Migration 11 and executes legacy conversion automatically.
- **Downgrade Boundary:** Databases updated to schema version 11 cannot be opened by older application binaries (e.g. 0.5.2 or earlier) because their hardcoded schema ceiling is 10. Users must update the application before restoring version 11 backups.

# Technical Appendices

## Appendix A: Additive Schema & SQL Invariants (Addressing M2S-R1 & M2S-R2)

```sql
-- Migration 0011_practice_sessions.sql
-- Additive tables for durable, versioned, resumable practice tests.

-- 1. Versioned practice tests (anchors items and historical attempts)
CREATE TABLE IF NOT EXISTS practice_test_versions (
    id                    TEXT PRIMARY KEY,
    source_material_id    TEXT REFERENCES study_materials(id) ON DELETE SET NULL,
    source_material_title TEXT NOT NULL,
    version_number        INTEGER NOT NULL DEFAULT 1,
    provider              TEXT NOT NULL DEFAULT 'gemini',
    model                 TEXT NOT NULL DEFAULT '',
    title                 TEXT NOT NULL DEFAULT '',
    content_hash          TEXT NOT NULL,
    created_at            TEXT NOT NULL,
    is_active             INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0, 1))
);

-- At most one active version per study material
CREATE UNIQUE INDEX IF NOT EXISTS uq_active_practice_version
    ON practice_test_versions(source_material_id)
    WHERE is_active = 1 AND source_material_id IS NOT NULL;

-- 2. Stable practice questions belonging to a test version
CREATE TABLE IF NOT EXISTS practice_test_items (
    id            TEXT PRIMARY KEY,
    version_id    TEXT NOT NULL REFERENCES practice_test_versions(id) ON DELETE CASCADE,
    ordinal       INTEGER NOT NULL,
    question_text TEXT NOT NULL,
    options_json  TEXT NOT NULL,
    correct_index INTEGER NOT NULL,
    explanation   TEXT NOT NULL DEFAULT '',
    source_page   INTEGER,
    UNIQUE(version_id, ordinal)
);

CREATE INDEX IF NOT EXISTS idx_practice_items_version
    ON practice_test_items(version_id, ordinal);

-- 3. Individual user attempts on a specific test version
CREATE TABLE IF NOT EXISTS practice_attempts (
    id                    TEXT PRIMARY KEY,
    version_id            TEXT NOT NULL REFERENCES practice_test_versions(id) ON DELETE RESTRICT,
    source_material_id    TEXT REFERENCES study_materials(id) ON DELETE SET NULL,
    source_material_title TEXT NOT NULL,
    started_at            TEXT NOT NULL,
    completed_at          TEXT,
    status                TEXT NOT NULL CHECK (status IN ('in_progress', 'completed', 'abandoned')),
    total_questions       INTEGER NOT NULL,
    answered_count        INTEGER NOT NULL DEFAULT 0,
    correct_count         INTEGER NOT NULL DEFAULT 0,
    incorrect_count       INTEGER NOT NULL DEFAULT 0,
    dont_know_count       INTEGER NOT NULL DEFAULT 0,
    score_percent         REAL
);

CREATE INDEX IF NOT EXISTS idx_practice_attempts_material
    ON practice_attempts(source_material_id, status);

-- 4. Recorded responses per item within an attempt
CREATE TABLE IF NOT EXISTS practice_responses (
    id             TEXT PRIMARY KEY,
    attempt_id     TEXT NOT NULL REFERENCES practice_attempts(id) ON DELETE CASCADE,
    item_id        TEXT NOT NULL REFERENCES practice_test_items(id) ON DELETE CASCADE,
    selected_index INTEGER,
    is_dont_know   INTEGER NOT NULL DEFAULT 0 CHECK (is_dont_know IN (0, 1)),
    is_correct     INTEGER NOT NULL DEFAULT 0 CHECK (is_correct IN (0, 1)),
    answered_at    TEXT NOT NULL,
    UNIQUE(attempt_id, item_id),
    CHECK ((is_dont_know = 1 AND selected_index IS NULL) OR (is_dont_know = 0 AND selected_index >= 0))
);

CREATE INDEX IF NOT EXISTS idx_practice_responses_attempt
    ON practice_responses(attempt_id);

-- 5. Trigger enforcing that an item belongs to the attempt's version
CREATE TRIGGER IF NOT EXISTS trg_enforce_response_item_version
BEFORE INSERT ON practice_responses
FOR EACH ROW
BEGIN
    SELECT RAISE(ABORT, 'Item does not belong to attempt version')
    WHERE (
        SELECT version_id FROM practice_attempts WHERE id = NEW.attempt_id
    ) != (
        SELECT version_id FROM practice_test_items WHERE id = NEW.item_id
    );
END;

-- 6. Trigger handling material deletion cleanup (Policy A)
CREATE TRIGGER IF NOT EXISTS trg_cleanup_material_delete
AFTER DELETE ON study_materials
FOR EACH ROW
BEGIN
    -- Delete unfinished and abandoned attempts for the deleted material
    DELETE FROM practice_attempts
    WHERE source_material_id IS NULL AND status IN ('in_progress', 'abandoned');

    -- Deactivate detached versions
    UPDATE practice_test_versions
    SET is_active = 0
    WHERE source_material_id IS NULL AND is_active = 1;

    -- Prune versions that have zero completed attempts
    DELETE FROM practice_test_versions
    WHERE source_material_id IS NULL
      AND id NOT IN (SELECT DISTINCT version_id FROM practice_attempts WHERE status = 'completed');
END;

-- 7. Durable migration tracking for legacy practice_tests
ALTER TABLE practice_tests ADD COLUMN legacy_migrated_at TEXT;
ALTER TABLE practice_tests ADD COLUMN legacy_error TEXT;
```

## Appendix B: Normative Persistence Contracts & Wire Shapes (Addressing M2S-R2)

### Operation State Matrix
| Operation | Preconditions | State Transition | Concurrency & Idempotency Rules |
|---|---|---|---|
| `start_or_resume` | Material has active version. | Returns existing `in_progress` attempt if present, else creates new `in_progress` attempt. | Same `operation_id` returns identical attempt. Concurrent calls return the single active attempt. |
| `record_response` | Attempt must be `in_progress`. Item must belong to attempt version. | Upserts `practice_responses`. Increments `answered_count` if new item. | Re-submitting same choice is a no-op. Changing choice updates row and re-evaluates `is_correct`. Fails if attempt is `completed` or `abandoned`. |
| `complete_attempt` | Attempt must be `in_progress`. | Status becomes `completed`. `completed_at` set. Tallies derived on backend. | Replay with same `operation_id` returns identical completed snapshot. Attempt cannot be modified afterwards. |
| `retake_attempt` | Material has active version. | Any existing `in_progress` attempt marked `abandoned`. New `in_progress` attempt created. | Replay with same `operation_id` returns new attempt. |
| `abandon_attempt` | Attempt must be `in_progress`. | Status becomes `abandoned`. `completed_at` set to now. | No score computed. Attempt cannot be resumed. |

All commands return allowlisted, sanitized codes: `INVALID_ARGUMENT`, `INVALID_STATE`, `NOT_FOUND`, `OPERATION_CONFLICT`, `STORAGE_ERROR`.

## Appendix C: Migration, Legacy Conversion & Writer Integration Plan (Addressing M2S-R3)

### Execution Sequence
1. **Migration 11 DDL:** Executes standard SQL creating tables, indices, triggers, and adding `legacy_migrated_at` and `legacy_error` columns to `practice_tests`.
2. **Startup Conversion Runner:** Runs automatically on application database initialization inside a single atomic transaction:
   - Queries `SELECT * FROM practice_tests WHERE legacy_migrated_at IS NULL AND legacy_error IS NULL`.
   - For each row: parses `questions_json`.
   - If JSON is valid and questions array is non-empty:
     - Generates version UUID = `uuid_v5(DNS_NAMESPACE, material_id + generated_at)`.
     - Inserts `practice_test_versions` (v1, `is_active = 1`).
     - Inserts items with deterministic item UUIDs = `uuid_v5(DNS_NAMESPACE, version_id + ordinal)`.
     - Updates `practice_tests` setting `legacy_migrated_at = nowIso()`.
   - If JSON is malformed or invalid:
     - Updates `practice_tests` setting `legacy_error = 'MALFORMED_JSON'`.
     - Leaves original row intact; does not crash startup.
3. **Writer Hooks Updated in PR 1:**
   - **Gemini Save (`documentRepository.savePracticeTest`):** When generating a new or replacement test, the writer writes `practice_tests` (for backward compatibility), inserts a new row in `practice_test_versions` (v2, v3, etc.) with `is_active = 1`, marks previous active versions `is_active = 0`, marks any in-progress attempt on the old version `status = 'abandoned'`, and inserts all new questions into `practice_test_items`.
   - **Slice B Import (`save_structured_study_material_atomically`):** Slice B imports always create a new material. The command is updated to atomically insert version 1 into `practice_test_versions` and its items within the same `BEGIN IMMEDIATE` transaction.
   - **Material Deletion (`documentRepository.removeStudyMaterial`):** The delete transaction deletes the material row; SQLite triggers enforce Policy A (pruning unfinished attempts, deactivating versions, and pruning unused inactive versions).

## Appendix D: Requirement-to-Test Verification Matrix

| Requirement | Test Scenario | Test Layer | Expected Result |
|---|---|---|---|
| **REQ-01: Interrupted Resume** | Start attempt, answer 3 questions, close connection, reopen, call `start_or_resume`. | Rust & Vitest | Returns same attempt ID with 3 confirmed responses; next index is 3. |
| **REQ-02: Idempotent Responses** | Send duplicate `record_response` with identical `operationId`. | Rust & Vitest | Returns success; exactly one response row stored; count unchanged. |
| **REQ-03: Conflicting Operation Retry** | Send same `operationId` with a different `selectedIndex`. | Rust & Vitest | Rejected with `OPERATION_CONFLICT`. |
| **REQ-04: Distinct "I Don't Know"** | Record response with `isDontKnow: true, selectedIndex: null`. | Rust & Vitest | Stored as `is_dont_know = 1, is_correct = 0`; counted in `dont_know_count`. |
| **REQ-05: Contradictory Flag Rejection** | Attempt insert with `is_dont_know = 1` and `selected_index = 2`. | Rust & Vitest | Rejected by SQL CHECK constraint. |
| **REQ-06: Cross-Version Item Rejection** | Record response referencing an item from a different test version. | Rust & Vitest | Rejected by trigger `trg_enforce_response_item_version`. |
| **REQ-07: Completed Attempt Mutation** | Send `record_response` to an attempt with `status = 'completed'`. | Rust & Vitest | Rejected with `INVALID_STATE`. |
| **REQ-08: Exactly-Once Completion** | Call `complete_attempt` twice on the same attempt. | Rust & Vitest | First call calculates score; second call returns identical cached result. |
