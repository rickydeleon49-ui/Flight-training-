#### Inspection of Historical Tag `v0.5.1` (`2dbf6df3f66b18e087b5842fc554f8e733255a0e`)

1. **Migrations stop at 8:** `src-tauri/migrations/` in `v0.5.1` contains only `0001` through `0008_notes.sql`.

### 3.3 Deep dive: Decision D2 (Create-new only vs. deferred replacement)

#### Proposed Flow: Create-New Only
- Every successful import produces a **new** `StudyMaterial` record with its own minted ID.
- The packet's guide (if present) is attached to the new material as an `ai_study_sets` row.
- The packet's test (if present) is attached to the new material as a `practice_tests` row.
- If the user imports the same packet file twice, two distinct materials are created. The preview modal informs the user: *"Will be imported as a new material."*

#### Why Replacement is Deferred
1. **Destructive Risk:** Today's schema has only one study set and one practice test per material. Replacing a study set completely overwrites existing flashcards and questions. If a user inadvertently targets an existing material, their prior notes and AI-generated study aids are permanently lost.
2. **Missing Versioning:** Version history and attempt tracking do not exist yet (scheduled for M2). Once M2 exists, replacement can create a new version while retaining the old version.
3. **Safety and Simplicity:** Create-new requires zero confirmation diffs, zero fingerprinting of existing rows, and cannot corrupt or delete prior data.

### 4.2 Hashing separation: Original-file hash vs. Canonical-content hash

A critical requirement of the contract (§3.5) is maintaining strict separation between two different hashes:

1. **Original-File SHA-256 (`originalFileSha256`):**
   - **Where computed:** In Rust (`src-tauri/src/study_packet.rs:107`), computed over the exact raw disk bytes read from the filesystem, including any UTF-8 BOM.
   - **Purpose:** Purely for display in the preview dialog and logs as a receipt for the user's reference (verifying which physical file was picked).
   - **Exclusion:** Never used for database deduplication, entity identity, or idempotency, because whitespace formatting, key ordering, and metadata comments would alter it without altering the study content.
2. **Canonical-Content SHA-256 (`contentHash`):**
   - **Where computed:** In TypeScript, computed by taking the SHA-256 of the UTF-8 bytes of `canonicalPersistenceJson(payload)`.
   - **Structure:** Defined in `src/logic/studyPacket/payload.ts:114-136`:
     ```json
     [
       "hfd-study-packet-content/1",
       ["Material Title"],
       ["import", "", "Title", "Summary", [["Heading", "Body"]], [["Front", "Back", null]], "Source Notes"],
       ["import", "", "Title", [["Question", ["Choice A", "Choice B"], 0, "Explanation", null]]]
     ]
     ```
   - **Properties:** Deterministic fixed-order JSON array. Completely excludes preview-only source claims, export IDs, choice IDs, item-level references, and file formatting. Changing an answer, card, heading, or source note changes this hash; changing key order or claims does not.
   - **Purpose:** Carried in `StructuredImportSaveOperation` as an operational digest.

### 4.3 Native IPC decoding boundary, exact types, and error shapes — corrected for BPREP-R3

#### 1. The Tauri Argument Decoding Problem and the Application Boundary
In locked Tauri **2.11.5**, `CommandArg::from_command` deserializes command parameters before executing the function body (`ipc/command.rs:61-69`). If the command declares a strongly-typed argument `operation: StructuredImportSaveOperation` with Serde `#[serde(deny_unknown_fields)]`, any unexpected key, missing field, or type error causes Serde to fail during argument extraction.
- **Exposure:** Serde's default diagnostic echoes the unknown field name (`"unknown field 'foo', expected one of..."`, `serdeCore 1.0.229: src/de/mod.rs:269-281`). If an adversary or caller passes a synthetic key containing sensitive data (e.g., `"apiKey_secret"`), that raw string is echoed.
- **Bypass:** The error occurs in the Tauri framework macro before the command body runs, bypassing any custom internal error mapper and returning a raw framework `InvokeError` string.

**The Corrected Application Decoding Boundary:**
The command accepts the operation payload as an untyped `serde_json::Value`. The command body executes on a background worker thread (`spawn_blocking`) and performs explicit application-level decoding and validation before touching the database:

```rust
#[tauri::command]
pub async fn save_structured_study_material_atomically(
    operation: serde_json::Value,
    state: State<'_, AppState>,
) -> Result<NativeImportSaveResult, NativeImportSaveError>
```

Within the command:
1. Validates that `operation` is a JSON Object.
2. Performs strict decoding where unexpected keys at the root level or in any nested structure (`material`, `studySet`, `practiceTest`, `sections`, `flashcards`, `questions`, `options`) are explicitly rejected.
3. Catching ANY decoding, validation, or deserialization error maps it immediately to an allowlisted, static application error (`INVALID_ARGUMENT`), **never echoing raw Serde error messages, unknown key names, database error strings, or payload content**.
4. Distinguishes application failures from outer transport failures: If Tauri fails to parse the outer JSON invoke envelope itself or if IPC transport disconnects, the frontend TypeScript adapter intercepts the rejected promise and maps it to a sanitized `IPC_TRANSPORT_ERROR` code.

### 4.4 Idempotency vs. conflict: comparing actual stored content — corrected for BPREP-R3

The native transaction **never trusts the client-supplied `contentHash` as proof of equality**. Instead, equality is determined by inspecting the actual stored database rows:

1. When `material_id` exists in `study_materials`:
   - Query stored `study_materials.title`. If `stored.title != op.material.title`, refuse with `IDEMPOTENCY_CONFLICT`.
   - Check non-content default fields: If material was not created as an imported custom material (`material_type != 'study_guide'`), refuse with `IDEMPOTENCY_CONFLICT`.
   - *Note on mutable metadata:* User-mutable metadata (such as `is_favorite`, review flags, or last accessed timestamp) are deliberately **excluded** from content equality comparison.
2. Inspect `ai_study_sets`:
   - If incoming has `studySet != null` and stored has no study set (or vice versa), refuse with `IDEMPOTENCY_CONFLICT` (presence change).
   - If both have study set: compare stored `title` (must equal import `studySet.title`), `provider` (`"import"`), `model` (`""`), `summary`, parsed `sections_json`, parsed `flashcards_json` (including `sourcePage == null`), and stored `source_notes`.
   - If stored `source_notes` differ, refuse with `IDEMPOTENCY_CONFLICT` (notes-only conflict).
   - If any title, section, card, or note field differs, refuse with `IDEMPOTENCY_CONFLICT`.
3. Inspect `practice_tests`:
   - If incoming has `practiceTest != null` and stored has no test (or vice versa), refuse with `IDEMPOTENCY_CONFLICT` (presence change).
   - If both have test: compare stored `title` (must equal import `practiceTest.title`), `provider` (`"import"`), `model` (`""`), and parsed `questions_json` (question text, options array, correctIndex, explanation, and `sourcePage == null`).
   - If any question, option, answer, explanation, or sourcePage differs, refuse with `IDEMPOTENCY_CONFLICT`.
4. Result:
   - If all canonical stored content matches the incoming operation payload: commit transaction and return `Ok(NativeImportSaveResult::AlreadySaved { materialId })`.
   - If a client supplies a forged `contentHash` matching a prior save but changes the payload: the stored content comparison detects the difference and returns `IDEMPOTENCY_CONFLICT`.
   - If an unrelated material was created with the same ID: returns `IDEMPOTENCY_CONFLICT`.

### 4.5 Complete sql.js database connection lifecycle — corrected for BPREP-R4

#### The Problem: Connection Invariant Reset on Export
The locked and installed `sql.js` version is **1.14.2**. Calling `db.export()` internally closes/reopens or serializes the database, which resets per-connection PRAGMAs back to SQLite defaults. In particular, `PRAGMA foreign_keys = ON` becomes `0` (OFF). Furthermore, creating a new `SQL.Database(snapshotBytes)` also starts with `foreign_keys = 0`.
- **Measured Probe Confirmation:** A synthetic in-memory probe (`docs/evidence/structured-study-import-slice-b-rereview-2026-10-03/sqljs-lifecycle-probe.cjs`) confirmed that `PRAGMA foreign_keys` reverts to 0 immediately after `db.export()`. If not reinitialized, subsequent transactions accept foreign-key orphan rows and fail to execute cascades.

#### One Explicit Connection Initializer
All connection creation, export, and recovery transitions must run through one canonical connection initializer:

```ts
function initializeConnection(db: SqlJsDatabaseHandle): void {
  db.run("PRAGMA foreign_keys = ON;");
  const result = db.exec("PRAGMA foreign_keys;");
  if (result[0]?.values[0]?.[0] !== 1) {
    throw new Error("Connection invariant violation: PRAGMA foreign_keys could not be enabled.");
  }
}
```

#### The Four Execution Points
`initializeConnection(db)` runs and verifies invariants at exactly four lifecycle points:
1. **Initial Open:** In `createSqlJsDatabase()`, immediately after instantiating `new SQL.Database(savedBytes ?? undefined)`. It also re-runs immediately after the initial migration save export completes.
2. **Pre-Operation Snapshot Export:** Immediately after taking `preOpSnapshot = cell.current.export()` and **before** executing `BEGIN IMMEDIATE`.
3. **Durable Export:** Immediately after calling `db.export()` during durable persistence and **before** releasing ownership or returning success to the caller.
4. **Replacement Recovery:** Immediately after instantiating `new SQL.Database(preOpSnapshot)` and **before** assigning the restored handle to `cell.current` and exposing it to any callers.

#### Handle Ownership, Statement Lifecycle, and Queueing
1. **Mutable Indirection Cell:**
   ```ts
   interface DatabaseCell {
     current: SqlJsDatabaseHandle;
     isUsable: boolean;
   }
   ```
   All repository methods (`select`, `execute`, `saveDebriefAtomically`, `saveStructuredImportAtomically`, `persist`) resolve the live handle via `cell.current`.
2. **Prepared Statement Lifecycle:**
   `sql.js` exports invalidate active prepared statements. No prepared statement may cross an asynchronous turn or outlive a transaction. All queries must strictly use `try { ... } finally { stmt.free(); }`.
3. **Serialized Access (`saveMutex`):**
   A FIFO lock queue serializes all writes, exports, and recoveries. Unrelated operations cannot interleave during transaction execution or recovery.
4. **Account for Every Handle User:**
   - `select`: checks `cell.isUsable`, queries `cell.current`.
   - `execute`: checks `cell.isUsable`, acquires `saveMutex`, executes on `cell.current`, exports, runs `initializeConnection(cell.current)`, writes to `localStorage`, releases `saveMutex`.
   - `saveDebriefAtomically`: checks `cell.isUsable`, acquires `saveMutex`, takes pre-op snapshot, initializes, runs debrief statements, commits, exports, initializes, writes to `localStorage`, releases `saveMutex`.
   - `saveStructuredImportAtomically`: checks `cell.isUsable`, acquires `saveMutex`, takes pre-op snapshot, initializes, runs `BEGIN IMMEDIATE`, inserts rows, runs `COMMIT`, calls `persistDurable(cell.current)` (which exports, initializes, and writes to `localStorage`), releases `saveMutex`.
   - `persist()`: checks `cell.isUsable`, acquires `saveMutex`, exports, initializes, writes to `localStorage`, releases `saveMutex`.

#### Exception Handling, Failure Phases, and Safe Refusal / Poisoning
1. **Phase A: Failure BEFORE Storage Changes (Snapshot or Transaction Error):**
   - If pre-op snapshot export throws or reinitialization fails: the transaction was **never started**. `localStorage` is completely untouched. If reinitialization failed, the handle cannot be trusted; the adapter poisons itself (`cell.isUsable = false`), throws `ConnectionInvariantError`, and refuses subsequent operations.
   - If a statement fails between `BEGIN` and `COMMIT`: execute `ROLLBACK;`. The in-memory handle remains intact and consistent (standard SQLite rollback). `localStorage` is completely untouched.
2. **Phase B: Failure AFTER Commit During Export or LocalStorage Write:**
   - Commit has succeeded in-memory, but durable export throws (OOM) or `localStorage.setItem` throws (`QuotaExceededError`).
   - Prior `localStorage` bytes are completely preserved.
   - Live in-memory handle has committed unpersisted changes.
   - **Recovery Execution:**
     * Instantiate clean handle: `const restoredDb = new SQL.Database(preOpSnapshot);`
     * Reinitialize invariants: `initializeConnection(restoredDb);`
     * If both succeed: `cell.current.close(); cell.current = restoredDb;`. The in-memory state is reverted to match durable storage.
     * Throw typed `StorageDurabilityError("Study packet could not be saved to durable browser storage.")`.
     * **Retry Semantics:** A subsequent retry will cleanly re-execute because `materialId` is no longer in memory. Prior unrelated rows are preserved.
3. **Double Failure and Safe Refusal:**
   - If `new SQL.Database(preOpSnapshot)` or its subsequent `initializeConnection` throws (e.g. browser out of memory):
   - The adapter cannot guarantee consistency or referential enforcement.
   - The adapter sets `cell.isUsable = false`.
   - All subsequent calls to `select`, `execute`, `saveDebriefAtomically`, or `saveStructuredImportAtomically` immediately throw `DatabaseDisabledError("Database adapter is disabled due to an unrecoverable persistence recovery failure. Page reload required.")`.

*Contingency: This adapter lifecycle design is strictly contingent on the accepted A2 implementation. No production code is modified in this Slice B preparation assignment.*

### 4.6 Strict refusal when atomic adapter is unavailable

Her Flight Deck enforces zero data loss: **multi-row operations must be atomic.**
- If `db.saveStructuredImportAtomically` is undefined on the current `SqlDatabase` driver, `documentRepository.importStudyPacket(operation)` immediately throws `AtomicPersistenceUnsupportedError`.
- **Prohibition:** The repository must NEVER attempt sequential fallback calls (`create` followed by `saveAiStudySet` followed by `savePracticeTest`).

## 6. Scope boundaries and prohibitions

To prevent scope creep and protect the stability of Her Flight Deck, the following boundaries are strictly enforced for Slice B:

### In Scope for Slice B:
- Adding `save_structured_study_material_atomically` to `src-tauri/src/study_packet.rs` with application decoding boundary, pinned rusqlite connection, `BEGIN IMMEDIATE`, busy timeout, defensive revalidation, and stored-content idempotency.
- Adding `saveStructuredImportAtomically` to `SqlDatabase` in `src/data/db.ts` and implementing it in `src/data/tauriDb.ts` and `src/data/sqlJsDb.ts` (with `initializeConnection` invariant enforcement, observable throwing flush, and snapshot recovery).
- Updating `src/domain/types.ts` to widen `provider` to `"gemini" | "import"`.
- Updating mappers and queries in `src/data/repositories/documentRepository.ts` to support `provider: "import"` with allowlist fallback.
- Refusing import with `AtomicPersistenceUnsupportedError` if the database adapter lacks atomic save support.
- Creating `ImportStudyPacketDialog.tsx` using `Dialog.tsx` with full A3 accessibility fallback.
- Adding "Import study packet…" entry point to `StudyLibrary.tsx`.
- Updating `MaterialDetail.tsx` to render imported-content titles, badges, and disclaimers when `provider === "import"`.
- Adding confirmation warning when regenerating Gemini content for a material that holds imported content.
- Unit and integration tests for all rows in §5.

### Strictly Out of Scope for Slice B:
- **No schema migrations:** No new SQL migration files in `src-tauri/migrations/`. Schema remains at version 10.
- **No replacement flow:** Replacing an existing material's guide or test is deferred (Decision D2).
- **No new production dependencies:** No `react-markdown`, `remark-gfm`, or other npm packages. (Markdown rendering is Slice C).
- **No external network calls:** Import is 100% offline. No telemetry, no Claude API, no Codex API, no Gemini calls during import.
- **No raw file retention:** Packet JSON is not copied into `documents/` (Decision D4).
- **No attempt tracking:** Question attempt history and durable item versions belong to M2.
- **No installer, signing, or release distribution:** Packaging, DMG creation, and signing remain governed by separate release runbooks.
