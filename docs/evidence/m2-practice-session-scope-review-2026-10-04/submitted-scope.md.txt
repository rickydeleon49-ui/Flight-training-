## 1. User Experience: Before, After, and Scope Boundaries

### Before (Current Main / Slice B Baseline)
- Practice tests for both Gemini and imported study packets exist in the `practice_tests` table (one row per source material, storing a JSON array of questions without stable item IDs).
- [PracticeTestPanel.tsx](file:///Users/rickymac/code/Flight-training-pr70-integration/src/pages/StudyLibrary/PracticeTestPanel.tsx) keeps the test index, selected answer, and score strictly in transient React memory (`useState`).
- Navigating to another tab, switching materials, closing the window, or quitting the app immediately destroys all in-progress answers and scores.
- "Retake this test" simply resets in-memory component state back to question 0; previous attempts leave no trace.
- Regenerating a test via Gemini or re-importing immediately overwrites the single `practice_tests` row (keyed on `updatedAt`), which would invalidate or corrupt any ongoing attempt.
- The user has no way to say "I don't know" or "Skip for now"; guessing is forced, distorting study feedback.
- The score screen shows an uncontextualized fraction ("X of Y correct") without distinguishing guessed from mastered questions.

### After (Proposed First Increment)
- **Start or Resume:** Opening a practice test on any material (Gemini or imported) automatically resumes any existing in-progress attempt or allows starting a fresh one.
- **Durable Progress:** Answering a question or choosing "I don't know" saves immediately and atomically to SQLite via background transaction.
- **Interruption Tolerance:** The user can close the app, sleep their Mac, or switch tabs mid-test; returning to the material restores their exact position, prior answers, and remaining questions with an honest status badge (*"In progress — 7 of 15 answered"*).
- **Distinct "I Don't Know":** A first-class choice alongside multiple-choice options. It is tallied separately from wrong guesses and unanswered questions, rewarding honest self-assessment.
- **Trustworthy Completion:** Submitting the final question computes an immutable, native/server-verified snapshot (`correct`, `incorrect`, `dont_know`, `unanswered`, `score_percent`).
- **Educational Review:** The completed screen clearly displays the score alongside a breakdown of missed and skipped questions with explanations and source references.
- **Version Isolation:** Regenerating the practice test creates a new content version. Historical completed attempts remain immutably anchored to the exact questions and choices the student actually answered.
- **Fresh Retakes:** Clicking "Retake this test" archives the completed attempt and starts a clean attempt on the latest active version.

### Explicit Scope Boundaries
- **Included in this increment:** Single-material practice tests (Gemini and imported); durable in-progress attempt resume; atomic per-question persistence; explicit "I don't know"; immutable completed attempt snapshots; review of missed/"I don't know" items; retake flow; content versioning on regeneration; additive migration 11 with safe legacy conversion.
- **Explicitly deferred to later increments:** Multi-material / library-wide quiz sessions; flashcard spaced repetition (FSRS / scheduler, M2-3); PDF viewer navigation / inline highlight jumps (M4); AI debrief question generation; official FAA certification / readiness claims; voice coaching / oral exam simulation; replacement import flows.

## 2. Implementation Strategy: Two-PR Increment vs. Single PR

We recommend structuring this scope into **two tightly connected, sequential PRs** rather than a single monolithic change:

```text
PR 1: Foundation & Persistence (Backend/Repository)
  ├── Migration 0011_practice_sessions.sql (additive tables + legacy upgrade)
  ├── Native atomic commands (rusqlite: start, respond, complete, retake)
  ├── Browser/test transaction mirror (sqlJsDb durable write + node:sqlite)
  ├── Repositories & domain models (PracticeSessionRepository)
  └── Comprehensive contract & persistence tests (zero UI changes)
        │
        ▼ (Merged after independent review)
PR 2: User Interface & Interaction (Frontend Polish)
  ├── Updated PracticeTestPanel.tsx (resume state, "I don't know", keyboard nav)
  ├── MaterialDetail.tsx integration (resume banner, past results summary)
  └── End-to-end UI regression tests (interruption, retake, review display)
```

### Concrete Tradeoff:
- **Single Monolithic PR:** Involves ~1,800 lines across Rust Tauri commands, SQL migrations, TypeScript adapters, repositories, and React UI components. Review fatigue increases the risk of subtle persistence or concurrency oversights.
- **Two Sequential PRs (Recommended):** PR 1 locks down data integrity, schema migration checksums, native atomic transactions, legacy data safety, and backup/restore round trips with automated tests. PR 2 is then implemented strictly against proven, working repository contracts without backend uncertainty. Total development pace is faster because verification boundaries are clean and isolated.

## 5. Backup, Downgrade & Lifecycle Policies

- **Archive Integrity:** New tables (`practice_test_versions`, `practice_test_items`, `practice_attempts`, `practice_responses`) reside inside the primary SQLite database. The existing backup engine ([src-tauri/src/backup.rs](file:///Users/rickymac/code/Flight-training-pr70-integration/src-tauri/src/backup.rs)) automatically captures them during standard ZIP archive creation with zero custom archive serialization code required.
- **Restore Compatibility:**
  - Backups created by version 11 will be inspected by `backup.rs`. If restored into an older application build (version 10 or earlier), `backup.rs` line 424 checks `newest_migration > CURRENT_SCHEMA_VERSION` and cleanly rejects the restore with the standard message: *"That backup was created by a newer database format. Update the app first."*
  - Older backups (versions 1–10) restored into version 11 pass validation, unpack the database, and execute migration 11 automatically on first launch.
- **Foreign Key Enforcement:** `foreign_keys = ON` is enforced at all times. When a source material is deleted:
  - Active test versions set `source_material_id = NULL`.
  - Attempts set `source_material_id = NULL`.
  - Cascades safely remove items when a version is deleted, and responses when an attempt is deleted.

# Technical Appendix

## Appendix A: Proposed Additive Schema (Migration 11 Sketch)

```sql
-- Migration 0011_practice_sessions.sql
-- Additive tables for durable, versioned, resumable practice tests.

-- 1. Versioned practice tests (anchors items and historical attempts)
CREATE TABLE IF NOT EXISTS practice_test_versions (
    id                    TEXT PRIMARY KEY,
    source_material_id    TEXT REFERENCES study_materials(id) ON DELETE SET NULL,
    source_material_title TEXT NOT NULL,
    version_number        INTEGER NOT NULL DEFAULT 1,
    provider              TEXT NOT NULL DEFAULT 'gemini',
    model                 TEXT NOT NULL DEFAULT '',
    title                 TEXT NOT NULL DEFAULT '',
    content_hash          TEXT NOT NULL,
    created_at            TEXT NOT NULL,
    is_active             INTEGER NOT NULL DEFAULT 1
);

CREATE INDEX IF NOT EXISTS idx_practice_versions_material
    ON practice_test_versions(source_material_id, is_active);

-- 2. Stable practice questions belonging to a test version
CREATE TABLE IF NOT EXISTS practice_test_items (
    id            TEXT PRIMARY KEY,
    version_id    TEXT NOT NULL REFERENCES practice_test_versions(id) ON DELETE CASCADE,
    ordinal       INTEGER NOT NULL,
    question_text TEXT NOT NULL,
    options_json  TEXT NOT NULL,
    correct_index INTEGER NOT NULL,
    explanation   TEXT NOT NULL DEFAULT '',
    source_page   INTEGER,
    UNIQUE(version_id, ordinal)
);

CREATE INDEX IF NOT EXISTS idx_practice_items_version
    ON practice_test_items(version_id, ordinal);

-- 3. Individual user attempts on a specific test version
CREATE TABLE IF NOT EXISTS practice_attempts (
    id                    TEXT PRIMARY KEY,
    version_id            TEXT NOT NULL REFERENCES practice_test_versions(id) ON DELETE RESTRICT,
    source_material_id    TEXT REFERENCES study_materials(id) ON DELETE SET NULL,
    started_at            TEXT NOT NULL,
    completed_at          TEXT,
    status                TEXT NOT NULL CHECK (status IN ('in_progress', 'completed', 'abandoned')),
    total_questions       INTEGER NOT NULL,
    answered_count        INTEGER NOT NULL DEFAULT 0,
    correct_count         INTEGER NOT NULL DEFAULT 0,
    incorrect_count       INTEGER NOT NULL DEFAULT 0,
    dont_know_count       INTEGER NOT NULL DEFAULT 0,
    score_percent         REAL
);

CREATE INDEX IF NOT EXISTS idx_practice_attempts_material
    ON practice_attempts(source_material_id, status);

-- 4. Recorded responses per item within an attempt
CREATE TABLE IF NOT EXISTS practice_responses (
    id             TEXT PRIMARY KEY,
    attempt_id     TEXT NOT NULL REFERENCES practice_attempts(id) ON DELETE CASCADE,
    item_id        TEXT NOT NULL REFERENCES practice_test_items(id) ON DELETE CASCADE,
    selected_index INTEGER,
    is_dont_know   INTEGER NOT NULL DEFAULT 0,
    is_correct     INTEGER NOT NULL DEFAULT 0,
    answered_at    TEXT NOT NULL,
    UNIQUE(attempt_id, item_id)
);

CREATE INDEX IF NOT EXISTS idx_practice_responses_attempt
    ON practice_responses(attempt_id);

-- 5. Safe legacy migration: populate version 1 from existing practice_tests
-- Handled by custom Rust/TypeScript migration step to reliably parse JSON arrays
-- and mint deterministic UUIDs for existing questions.
```

## Appendix C: Requirement-to-Test Verification Matrix

| Requirement | Test Scenario | Automated Test Level | Expected Outcome |
|---|---|---|---|
| **REQ-01: Interrupted Resume** | Start attempt, answer 3 of 5 questions, close database, reopen, call `start_or_resume`. | Native Rust & Vitest | Returns existing attempt ID with 3 recorded answers; next uncompleted index is 3. |
| **REQ-02: Idempotent Responses** | Send duplicate `record_response` with same `operationId` or retry rapid clicks. | Native Rust & Vitest | Exactly one response row stored; `answered_count` is unchanged on duplicate. |
| **REQ-03: Distinct "I Don't Know"** | Record response with `isDontKnow: true, selectedIndex: null`. | Native Rust & Vitest | Stored with `is_dont_know = 1, is_correct = 0`; counted in `dont_know_count`, not guessed wrong. |
| **REQ-04: Exactly-Once Completion** | Call `complete` twice sequentially or concurrently with same attempt ID. | Native Rust & Vitest | State transitions once; second call returns identical completed snapshot; timestamps immutable. |
| **REQ-05: Version Isolation on Regen** | Complete attempt on v1, regenerate test (creates v2), start new attempt. | Native Rust & Vitest | Old attempt remains linked to v1 questions; new attempt starts against v2 questions; zero score cross-talk. |
| **REQ-06: Material Deletion Handling** | Delete study material with existing completed attempts. | Native Rust & Vitest | Material deleted; PDF deleted; attempt rows retained with `source_material_id = NULL` and preserved title snapshot. |
| **REQ-07: Corrupt Legacy Data** | Load database with malformed JSON string in `practice_tests.questions_json`. | Vitest & Rust | Migration 11 completes without error; corrupt row flagged; clean error message in UI. |
| **REQ-08: Provider Parity** | Run session lifecycle on a Gemini-generated test and an imported packet test. | Shared contract fixtures | Identical response structures, storage formats, and scoring behavior for both providers. |
| **REQ-09: Offline Isolation** | Execute full session lifecycle without internet or Gemini API key. | Full test suite | Zero network calls made; local SQLite handles all operations under 5ms. |
| **REQ-10: Backup Round Trip** | Create v3 backup with active and completed attempts; wipe data; restore archive. | Native Rust `backup.rs` test | All versions, items, attempts, and responses restored byte-for-byte; migration 11 intact. |
