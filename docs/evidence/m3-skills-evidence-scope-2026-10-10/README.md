## Limitations

- **The native write transaction is specified, not prototyped.** The TS transaction runs on the real node:sqlite and sql.js engines; rusqlite covers constraints, validation, upgrade and backup.
- **Bookkeeping differs.** The prototype records migrations in `schema_migrations`, not the desktop's `_sqlx_migrations` with its SHA-384 checksum.
- **The UI is jsdom only:** no WKWebView or installed-app claim. Benchmarks are source-level Node timings without peak memory.
- **Backups taken before an erase** still contain the erased content.
- **G1–G3 installed verification stays DEFERRED/UNEXECUTED/UNVERIFIED.** Post-receipt recovery stays BLOCKED/source-covered. No hfdtest request, app launch, provider call, installer, signing or release.
