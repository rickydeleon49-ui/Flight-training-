## GEN-FIX-1 — measured-rate interim allowance

**Outcome.** Give a moving upload enough total time, with the existing stage-specific explanations and a strict **600 s** ceiling. This remains a total allowance, not stall detection.

**Storage / migration.** No SQLite migration. Add optional versioned timing metadata to the existing journal draft: `policy`, `ceilingMillis`, `allowedMillis`, `remainingMillis`, `deadlineUtc`, `uploadBytes`, `sampleMillis`, `sampleBytes`. Keep samples only for this job; no PDF text, key, URL or persistent connection history. Old drafts retain their original allowance; never silently upgrade an interrupted job.

**Exact policy.** Keep connect timeout 15 s and existing durable request limits. Start with a 300 s allowance; while no trustworthy rate exists, use a bounded 600 s fallback. After ≥1 s and ≥64 KiB observed upload progress, sample each second. Use `r = 0.8 × min(cumulativeBytes/elapsedUploadSeconds, latestWindowBytes/windowSeconds)` in bytes/s, excluding zero/invalid samples.
Compute desired total seconds from job start as `ceil(elapsedJobSeconds + remainingUploadBytes/r + 210)`; clamp to `[300,600]`. Only increase a running allowance, never beyond 600 s from its original start. Persist an increase before further dispatch; keep the prior allowance if writing fails. A cache hit needs no upload estimate and starts at 300 s.
The 210 s reserve is 10 s processing + 180 s model + 20 s response/overhead. Diagnosis totals: 20 MB/1 Mbps needs 350.40 s; 50 MB/3 Mbps needs 323.47 s; 50 MB/1 Mbps needs 440.40–590.40 s. Its 400 s upload plus reserve clips to 600 s. All 27 idealized estimates fit, but the worst has only 9.60 s margin; retries, real processing or overhead can still fail. These are arithmetic assumptions, not measured provider latency.
Progress from a body producer/socket write is only an estimate; buffered writes can exaggerate the rate. Do not call it confirmed delivery. Missing, zero or unstable measurements use the 600 s fallback, never divide by zero or wait without a ceiling.

**IPC / commands.** Preserve `generate_study_aid`, `generate_practice_test` and cancel signatures. Extend internal Budget deadline control, upload progress callbacks and optional job/progress timing fields. Replace the outer guard's captured 300 s timeout with a guard that observes permitted extensions, itself bounded by 600 s. Fix `remaining_clock`, request timeout snapshots and `gemini_batches`' hard-coded 300 s initialization together; otherwise the interim change is ineffective.

**UI / provenance.** Retain Preparing, Uploading, Waiting for file, Generating, Reading, Validating and Pausing messages. Add “Your PDF is still uploading. A slower connection can take a little longer.” Keep Cancel visible. Timeout text names the stage and actual allowance; never infer model progress from elapsed time. Output remains labelled a Gemini study aid to check against FAA material and her instructor.

**Failure / restart.** Every retry, backoff and cleanup consumes the same allowance. Cancellation prevents later submissions. On reopen, show Interrupted; do not resend. Use `min(persistedRemaining, wallDeadline-now)` so clock rollback cannot create time; manual retry cannot silently replenish an old card draft. That limitation is deliberately replaced for section guides in GEN-02.

**Failing-first tests.** `rate_allowance_covers_estimate_table`, `rate_zero_missing_buffered_and_changing_samples`, `allowance_never_exceeds_600_from_original_start`, `outer_guard_observes_extension`, `restart_keeps_persisted_remaining`, `card_batches_use_selected_policy`, `cancel_during_rate_sample_stops_dispatch`. Re-express S1 upload/budget-remainder, S2 and S3 as success under a qualifying allowance; S4 early-drop retries may finish attempt two while preserving identical request bodies and one upload; retain S5 success and a deliberately over-cap failure.

**Files.** `src-tauri/src/{gemini.rs,gemini_budget.rs,gemini_files.rs,gemini_jobs.rs,gemini_batches.rs,gemini_slowlink_tests.rs,fake_gemini.rs}`, `src/services/gemini.ts`, `src/pages/StudyLibrary/GeminiJobNotice.tsx`, adjacent budget/job/UI tests.
**Risks / size.** Rate bias, timeout races, stale deadline closures and longer paid waits; **2–4 days**.
**Owner decision D1.** Default: approve the formula, conservative rate factor, unknown-rate fallback and **600 s maximum** as an interim policy; retain stage wording and existing request caps. No bandwidth setting or promise of success.

## GEN-FIX-2 — stage-aware stalls with an absolute cap

**Outcome / exact constants.** Supersede FIX-1's rate-based total allowance, retaining its progress instrumentation:

| Boundary | Recommended constant and reset rule |
| --- | --- |
| Connect | 15 s per connection, clipped to remaining absolute time |
| Upload inactivity | 60 s without positive body-transfer progress; positive bytes reset only this timer |
| Upload start/finalize headers and file lookup | 60 s per control response; upload-finalize wait starts after the last upload byte |
| PDF processing | 120 s total in WaitingForFile; successful polls do not reset it |
| Generation first headers | 480 s per admitted generation attempt; no 60 s no-byte rule while Gemini thinks |
| Response body inactivity | 60 s without positive response bytes, beginning when headers arrive |
| Validation | 30 s maximum, including cancellation checks in bounded parsing/validation work |
| Absolute | 900 s from invocation, covering every stage, retry, backoff and cleanup; never reset by progress |

Every effective timeout is the minimum of its stage boundary and the absolute time left. Stage changes do not replenish the absolute budget. Retain the existing three-attempt ordinary-generation cap and nine-submission card-batch ledger. A stage timeout can retry only when the existing error classification permits it and both time and request slots remain; absolute expiry is terminal.
Justification: 60 s tolerates intermittent transfer while detecting a stopped link; 480 s admits the 360 s S2 fixture and the table's 90/180 s thinking cases. The 900 s envelope admits a 400 s upload plus a 480 s first-header wait and modest processing/body time, but is not a success guarantee. Processing's 120 s is a proposed operational bound, not an observed provider requirement.

**Storage / migration.** No SQLite migration. Version FIX-1's journal timing object with policy `stage-v1`, absolute remaining/deadline, active stage and per-stage elapsed/remaining counters. Persist conservative remaining time before requests/checkpoints; reopen cannot restore extra time. Never serialize a monotonic Instant. Progress events alone are not durable checkpoints.
**IPC / commands.** No new public generation command. Replace total-only `.send()`/`.chunk()` waits with stage guards; use an observable bounded upload producer and response chunk loop. Enable reqwest's existing-crate stream feature if needed; no new dependency. Cancellation/admission checks must guard every dispatch, producer wake, poll and retry. Status/progress includes the stage and reason, not provider bodies or upload-session URLs.
**UI / provenance.** “The upload stopped moving. Your saved work is still here.” / “Gemini is taking longer to answer. You can try again.” / “The rest of the answer stopped arriving.” Preserve the existing stage names and useful diagnostics. Existing Gemini labels remain; partial JSON is never a finished or verified guide.
**Failure / restart.** Save validated checkpoints only; keep the prior checkpoint on malformed/truncated/oversized answers or disk failure. Reopen pauses work and requires her request. FIX-2 alone does not turn old card drafts into indefinitely resumable guides. Cleanup cannot extend the cap; remote cleanup is best effort and owned-file-only.

**Failing-first tests / exact flips.** Use the diagnosis's same fixture paths and 1:100 time scaling, with unscaled retry backoff explicitly accounted for:
- **S1 upload alone and budget remainder:** change timeout assertions to success while upload bytes keep moving, with exactly one generation request and one upload; no premature 300 s guard survives.
- **S2:** 360 s to headers now succeeds within 480 s; a 481 s no-header fixture fails in Generating unless an eligible retry fits the shared cap.
- **S3:** 400 s trickle now succeeds while each body gap is <60 s; a 61 s gap fails in Reading, despite ample absolute time.
- **S4 headers/body:** the early partial/drop still replays the entire unfinished unit; the second 360/400 s attempt succeeds within 900 s. Assert two identical generation bodies and one PDF upload; no retry after absolute expiry.
- **S5:** retains success. Add `upload_stall_61s`, `processing_120s_not_reset_by_polls`, `progress_cannot_extend_900s`, `header_grace_not_transfer_stall`, `restart_clock_rollback`, `cancel_at_each_stage`, and cancellation-versus-final-checkpoint races.

**Files.** FIX-1's native files plus `src-tauri/src/gemini_cancel.rs`, `src/state/GeminiJobs.tsx`, service/notice and adjacent tests; `src-tauri/Cargo.toml` only for existing-crate feature wiring if required, checking lockfile consistency.
**Risks / size.** Socket-buffer progress is imperfect; dribbling bytes consume the full cap; timer/cancel races and increased provider waits; **3–5 days**.
**Owner decision D2.** Default: 60 s transfer stalls, 480 s first headers, 120 s processing and **900 s absolute** with the other boundaries above; ship without SSE. Streaming is deferred because it neither fixes upload time nor makes partial schema JSON resumable.

Keep it out of IPC job records, logs, exports and backups. Reuse `gemini_files` validation/lease ownership, not arbitrary frontend URIs.

Changing the key invalidates reuse and requires an explicit Continue action. Adapt shutdown/disconnect retirement so paused references are retained until expiry or deliberate discard; delete only owned remote files with the correct key.
