## Findings and fixes

| Area | Evidence from current code | Result / action |
| --- | --- | --- |
| PDF opening | `documents::document_path` resolves an app-owned relative name under `app_config_dir()/documents`; `openDocument` passes it to `tauri-plugin-opener`; `default.json` scopes `open-path` and `reveal-item-in-dir` to `$APPCONFIG/documents/**`. The prior bare permission explained the reported “Not allowed to open path” failure. | Static scope test passes. The packaged `.app` must still open an imported PDF in Preview and reveal it in Finder. |
| Settings Open folder | `data_directory` returns `app_root`, the same path Settings displays and passes to `openPath`; opener scope includes `$APPCONFIG`. | Static scope test passes. Finder behavior remains a Mac smoke test; the same service keeps Windows Explorer behavior. |
| Complete backup | Migration 9 introduced `practice_tests`, but `backup.rs` still refused any database newer than schema 8. `create_complete_backup` validated the live database before snapshotting, so an upgraded app would reject its own backup. | Schema ceiling is 9 and is tested against the registered migration list. A version-9 database snapshots successfully; version 10 remains rejected. Existing v2 hash/integrity checks, `.part` validation before final rename, previous-file protection, and v1 restore tests remain. |
| Manual safety backup | `create_backup` copied a live SQLite database and WAL files separately. A concurrent write could make that copy inconsistent. | Manual copies now use SQLite's online snapshot with five-second busy timeout and three bounded retries. A test confirms committed WAL data appears in the saved copy. Startup pre-migration copies remain raw because they run before the frontend opens SQLite. |
| Automatic split records | `createMany` issued `BEGIN`, each insert, and `COMMIT` via separate `tauri-plugin-sql` pool operations. The plugin executes each call on the pool, so the statements were not pinned to one connection. This could cause locks, rollback errors, or half-saved parts. | Desktop parts and tags now use one Rust `rusqlite` immediate transaction. It checks app-owned part files, enables foreign keys, waits up to five seconds for a lock, then commits or rolls back. Frontend retries lock errors at 100/300/700 ms, with no unlimited loop. Rust tests cover commit and rollback; TypeScript test checks the native path avoids pooled transaction statements. |
| Manual split records | A single `create` could insert the material and fail while inserting tags; the UI might then delete the PDF but leave a record pointing to it. | Manual split now uses the same atomic batch transaction after a successful safety snapshot. PDF-range checks, 50 MiB rejection, and file cleanup remain. |
| Gemini rate limits | 429 was described as a *free* quota exhaustion and never retried, although paid projects also have rate and spending limits. | 429 now gets the same bounded backoff and backup-model attempt as transient server errors. The final message tells the user to check project limits/billing or wait, without claiming a free tier or invalid key. Both configured model IDs are listed in [Google's model documentation](https://ai.google.dev/gemini-api/docs/models); its [troubleshooting guidance](https://ai.google.dev/gemini-api/docs/troubleshooting) includes 429 among transient failures to retry with bounded exponential backoff. |

## Other audited behavior

- Automatic PDF splitting reads the original, windows each part, caps output at 50 MiB and 1,000 pages, labels part files in app-owned storage, and deletes generated files if Rust fails before returning. The UI creates separate records and exposes a study-guide action for each. Unit tests cover range and byte boundaries and source preservation; a real image-heavy PDF and Mac memory/progress behavior remain untested.
- A manual range takes first/last page and optional title. Invalid or over-1,000-page ranges are blocked; output over 50 MiB is refused and removed. If saving its record fails, the UI removes its generated file. The safety snapshot now precedes file and library changes.
- Study guides, flashcards, and practice tests use only the selected stored document. `generate_practice_test` and schema 9 already exist; malformed practice questions are filtered. No additional schema migration is currently needed. A real Gemini request, response, quota behavior, and quiz interaction still need smoke testing.
- The Gemini credential is saved separately in `gemini-key` with owner-only Unix permissions, is not returned by status, and is excluded from complete archives. **Unmet strict requirement:** Settings currently collects the key in a password field inside the webview and sends it to Rust via `configure_gemini`. It is transient webview state even though it is not in SQLite or backups. A native secure-entry UI is needed if “never enters the webview” is literal; do not claim that property today. No test credential or private PDF was used during this audit.
- `tauri.conf.json` declares `com.herflightdeck.app`, minimum macOS `12.0`, and a DMG-capable bundle. No custom entitlements, Info.plist, or PDF document type registration is present; file selection uses native open/save panels and PDFs are intended to open in the system default viewer. Do not change the identifier casually because it determines the app-owned data path. The release workflow documents unsigned first launch via Privacy & Security → Open Anyway. [GitHub's runner reference](https://docs.github.com/en/actions/how-tos/write-workflows/choose-where-workflows-run/choose-the-runner-for-a-job) lists `macos-15` as Apple Silicon; a successful build on macOS 15 does not prove runtime compatibility with macOS 12.

## Required Mac-only checklist before distribution

Use an Apple Silicon Mac, ideally test macOS 12 as well as a current macOS. Use a copy of non-sensitive data and keep the existing `v0.5.1` release/tag untouched.

1. On the Mac, check out the exact audit commit. Run `npm ci`, `npm test`, `npm run build`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, and `npm run tauri build -- --bundles dmg`. Confirm the filename ends `_aarch64.dmg` and inspect `Info.plist` for `LSMinimumSystemVersion = 12.0` and identifier `com.herflightdeck.app`.
2. Mount the generated DMG, copy the app to Applications, and launch it. Follow the documented unsigned-app Open Anyway path; record any Gatekeeper or “damaged” message instead of bypassing a genuinely corrupt DMG. Repeat on macOS 12 if support for 12 is promised.
3. Import a public PDF through the native open panel, move/delete the original upload, reopen the stored copy via **Open** in Preview, and use **Show in Finder**. In Settings, compare the displayed data path with the Finder folder opened by **Open folder**.
4. Split a large image-heavy PDF automatically; confirm progress continues, each labeled part is at most 50 MiB and 1,000 pages, each is a separate record with its own study-guide action, the original's hash is unchanged, and no SQLite lock alert appears. Force a failure (for example, a single oversized page) and check no partial files/records remain.
5. Manually split a valid range with and without a title. Try an invalid range and one whose output exceeds 50 MiB; verify clear rejection. Test a failure during record saving and confirm both rollback and file cleanup. Confirm the pre-change safety copy is restorable.
6. With a test Gemini key, generate a guide, flashcards, and practice test from a stored PDF; check model selection and answer/source handling. Trigger or mock a 429 and a 5xx and verify the bounded progress and final messages. Confirm the key is absent from logs and an exported archive. Treat the webview-entry limitation above as unresolved until native secure entry is implemented.
7. While autosave and splitting are active, save a complete `.hfdbackup` to Downloads. Verify it exists, opens as ZIP, contains `manifest.json`, `integrity.json`, the database and documents, and passes the app's inspect/restore validation. Re-export over an existing valid backup while forcing failure and confirm the previous file remains intact. Restore from the valid backup and verify records, attachments and practice tests.
8. Install the new build over a populated earlier version and confirm the pre-migration safety copy, data path, records, documents, and Gemini connection behavior. Repeat the applicable open/folder/backup checks on Windows to guard Explorer and install regressions.

Until that checklist is executed on an installed Mac app, this branch can be merged as an audited code fix but must **not** be described as Mac-ready or published by moving an existing release tag.
