## M4S1-R11 [P2] — old action completions can resurrect a retired repository

**Reproduced twice**, for checkPages and deleteBookmark. `src/state/navigation/useDocumentNavigation.ts` gives each reload a fresh latest id, but async actions capture the old reload closure and invoke it unconditionally in finally. Sequence:
1. Start an action on repository A and hold its upstream inspect/mutation.
2. Switch the mounted hook to repository B; its new read publishes B.
3. Release A's old action.
4. Its finally calls old reload, which allocates a newer id and publishes A over B.

The per-read generation protects reads that were already in flight; it does not protect retired work that starts a fresh read later. Existing follow-up tests keep the same context, so they miss this.

**Required fix:** bind actions and follow-up reloads to their initiating material/repository/lifetime context. A retired callback must return before starting an old read or advancing/invalidating the current context's read generation. Gate success/error/loading and prevent stale follow-up work from starving a pending current read. Keep legitimate same-context post-mutation reloads. Cover repository and material changes, upstream success/failure, checkPages and each mutation, unmount and StrictMode replay. Do not use a generic latest-read id as an action-context identity, since valid same-context reloads may overlap.

Frozen tests: `[R11] a retired checkPages completion cannot start an old-repository read` and the deleteBookmark variant. Actual final hash is A, expected B.

## M4S1-R12 [P2] — an old badge callback clears a newer request's cleanup ownership

**Reproduced**, with a passing single-request/unmount control. `src/pages/StudyLibrary/navigation/SourcePageBadge.tsx` stores the started epoch in a shared ref, then every obsolete completion does `if (result === null) started.current = null` without checking ownership.

Sequence: start held source request1; retire it; start held request2 from the same mounted badge; finish request1, whose null result clears request2's marker; unmount the badge; finish request2. Cleanup no longer knows it owns request2, so the document opens after unmount. The controller itself can retire a request correctly; the badge discarded the marker needed to invoke that retirement.

**Required fix:** each click owns a stable request marker; clear it only if it still belongs to that exact click. Include controller identity as well as epoch (different controllers can reuse the same numeric epoch), or use an equivalent unique local ticket. Cleanup must retain and retire the current owned request and must not cancel another badge's newer request. Cover old success/error/null completions, repeated clicks after retirement, controller replacement, unmount and normal success. Preserve guidance-only semantics and current content checks; no database state should be written by guidance.

Frozen test: `[R12] an older completion cannot erase a newer source request's unmount ownership`. Actual opener calls contain m after unmount; expected none.
