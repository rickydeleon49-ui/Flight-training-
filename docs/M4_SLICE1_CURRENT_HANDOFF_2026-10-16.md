2. **Four-table persistence:** use the current candidate's material_content_identities, material_bookmarks, material_reading_state AND material_operation_claims. Unknown originating hashes are nullable and visibly unverified; never restore the old draft's NOT NULL hash requirement. Recheck the next available migration number on current main, never edit shipped migrations, and register/checksum a genuinely new migration coherently through browser and Rust paths.
3. **Durable operations:** reserve exact increasing ownership under a serialized write transaction; require one affected claim row and exact read-back before returning a token. Commit only for the exact current non-cancelled claim, and write the complete page/hash/printed-label/status tuple atomically. Reject unreserved, stale, unreadable, cancelled and overflow ownership; failed mutations roll back without compensating page writes. Preserve close/reopen, deletion cascade and backup/restore behavior.
4. **Real asynchronous boundary:** the prototype's `node:sqlite` and JavaScript isCancelled closure are not production APIs. Establish equivalent native/browser operation ownership and cancellation across actual asynchronous calls. Retire old request work before any newer ownership read/reservation can fail; keep local request epochs distinct from durable generations. A held old opener/save/retry cannot publish or commit after supersession. Never serialize function predicates through Tauri or rely only on UI checks after the database already wrote.
5. **Trusted file identity:** derive hash/count from managed file bytes through a trusted native boundary, handling replacement between inspection and use. Do not trust caller-chosen totalPages, hash, status or absolute paths. Browser-mode limitations stay explicit; synthetic/browser transaction tests do not prove a real desktop file was inspected.
6. **UI:** accessible interactive source badges in the existing material/practice/card views, bookmark add/list/jump/delete, and a last-requested marker with distinct optional read confirmation. Failures must not imply success or confirmed reading. Keep progress scoped to the active material AND content, including a cross-material newer request whose ownership lookup fails. Provide visible save-only retry without reopening the PDF. Missing-file links can be unavailable while a separate restore/locate action stays reachable. Use existing components and modal fallback; preserve keyboard focus and warm nontechnical language.
7. **Native opening:** keep the existing default reader. If native opening cannot guarantee a page jump, honestly display the resolved physical page/printed label as guidance. A successful open request is not proof of the displayed page or reading completion. Do not change global permissions, change the bundle identifier or add embedded rendering dependencies.
8. **Backup and version safety:** apply the new schema only through the normal guarded migration path. Verify populated schema14 retention, exact ledger/checksums, all four navigation tables in backup/restore, rollback on faults, file drift and older-binary refusal.
